## 「Unity Hub 打开鸣佐英语没反应」—— ALREADY_OPEN 状态残留（17:12）

### 根因：Hub 内部记着"项目已打开"
- 现象：在 Hub 里点「鸣佐英语」毫无反应
- 证据（`%APPDATA%\UnityHub\logs\info-log.json`）：
  ```
  Error while opening project: {"code":400,"error":{"errorCode":"ALREADY_OPEN",
    "projectName":"鸣佐英语","projectVersion":"2022.3.1f1c1", ...}}
  ```
- 触发路径：我先前用命令行起的 Unity 卡在加载画面十几分钟占着锁，
  之后进程虽被回收，但 **Hub 里"该项目已打开"的会话记录没有清除**，
  于是 Hub 一直拒绝再次打开 —— 与项目本身、与锁文件都无关
- 修复：**完全退出 Unity Hub 再重新启动**（必须杀掉所有 `Unity Hub.exe` 子进程），
  重启后 Hub 的会话状态被重置，再打开项目即成功
- 重启后 Unity 正常启动，20 秒内窗口标题就从 `Untitled` 变成 `MainScene`，
  说明 `GameRunner` 的自动切场景修复同时生效

  Hierarchy 里 `CharacterModeCanvas` 独立于主 Canvas，融合正常

### 遗留：头像走兜底路径（已处理待编译）
- 现象：`Resources.Load<Sprite>("CharacterMode/naruto_avatar")` 返回 null，
  日志警告"没有 Sprite 子资源，已按贴图临时创建 Sprite"（画面仍能显示头像）
- 原因：`naruto_avatar.jpg.meta` / `sasuke_avatar.jpg.meta` 是**手写/工具生成的 meta**

- 处理：备份原 meta 到 `Build/meta-backup/`，删除两个头像 meta，
  让 Unity 重新导入生成标准 meta；
  **需退出 Play 模式后 Unity 才会重新导入**（Play 中不处理资源变化）
- 代码已有兜底（`LoadSprite` 用 Texture2D 现场造 Sprite），
  所以即使 meta 未重建，头像也能正常显示，不影响使用

### 关键技术发现：小怪是 Sprite 序列帧动画
- 敌人预制体是**二进制序列化**（非 ForceText），无法直接改内部 Sprite 引用
- `Enemy.Awake()` 里 `GetComponent<Animator>()`，动画片段名 `move/attack/damage/death`
- 贴图在 `Assets/GameRes/EnemySprites/image/larva/enemy/<怪物名>/{idle,run,attack,damage,dead,stun}/`
- **Animator 每帧都写 `SpriteRenderer.sprite`**，所以普通"进场景改一次 sprite"会被覆盖，
  必须在 `LateUpdate` 里覆盖（执行顺序排在动画之后）

    保证血条/单词窗口位置基本不变
  - 角色模式中途切换时同步换形象
  - `EnemySkinController.Enabled` 可一键关掉换皮

## 修复「无法选择佐助模式」（接上一节）

### 现象
首页左上角能点「鸣人」，点「佐助」没反应 / 变成鸣人；中途还出现过两块模式选择框，随后面板又消失。

### 根因（连锁，一层套一层）
1. **场景文件被写进了运行时 UI**：`MainScene.unity` 里残留了一整套
   `CharacterModeCanvas / CharacterModeRuntimeUI / CharacterModePanel`
   （日志特征：`GameObject (named 'CharacterModeRuntimeUI') references runtime script in scene file. Fixing!`）。
   来源：编辑器流程在 Play 之后调用过 `EditorSceneManager.SaveOpenScenes()`。
2. **两块面板**：残留对象反序列化后 private 字段（panel/avatar/button）全是 null，
   `Create()` 的复用判断 `current.avatar != null` 不成立 → 又建了一套 → 屏幕上两块。
3. **面板被压扁**：残留对象带着旧画布，**`Create()` 复用了它的 CanvasScaler（1080x1920 竖屏参考）**，

## 把模式选择框改成「场景常驻 UI」（接上一节）

### 用户反馈
"左上角的模式选择框看不见，无法切换模式，只能在 tools 的测试中看见，加进去"。
根因：面板是 `CharacterModeRuntimeUI.Create()` 在 **Play 模式下用代码创建**的，

- `Build(owner)` 拆成 **`BuildStructure()`**（public，不依赖管理器，编辑模式可调用）
  + `Bind(owner)`（运行时刷外观、绑回调）。

  否则在编辑器里看不到面板长什么样。

- `Create()` 先扫描场景：`IsIntact()` 为真的**常驻面板直接复用**，只有空壳才销毁重建。
- `IsIntact()` 由 internal 改 public（Editor 程序集要用）。

### 新增工具
`Assets/Editor/CharacterModePanelBuilder.cs` —— 菜单 **Tools/把模式选择框放进首页场景**

- **`EditorApplication.update` 里轮询请求文件，在编译刚结束时容易不执行**：
